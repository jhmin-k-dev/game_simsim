# 누룽이의 세계 — 영상미·움직임 품질기준

> **문서 상태: 초안(v0.1)**
> ★ = 07/08 문서에 근거가 있는 확정값. 표시 없는 값 = 제안값, 디렉터 확정 필요.
> §1-1 / §1-4 / §2-1 은 다른 문서가 번호로 참조하므로 **절 번호를 바꾸지 말 것**.

---

## 0. 이 문서의 지위

07 §4: **"M0(룩)+M1(움직임)에 전체의 40%. 여기 §1-1 체크 10개와 §2-1 스크린샷 테스트를 통과하기 전에는 배경 대량 생산(P4)으로 넘어가지 않습니다."**

즉 이 문서는 **관문**이다. 통과 못 하면 다음 단계로 가지 않는다. 애니메이션 외주(100~200만)를 쓸지 말지도 §1-1로 판정한다 ★ (07 §3-2, 08 A 하단).

**판정하는 사람은 디렉터다.** Claude Code 는 Unity 에디터 화면을 보지 못한다 ★ (07 §2-4). 아래 체크는 사람이 눈으로 본다.

## 1. 움직임

### 1-1. 통과 체크 10개 ★

> 07 §3-2, 07 §4, 08 A 하단이 "품질기준 §1-1"로 참조하는 절.
> **회색 박스 맵에서 5분 돌아다닌 뒤 판정.** 10개 중 **9개 이상 ○면 통과.**

| # | 체크 | ○의 기준 |
|---|---|---|
| 1 | **정지가 살아 있는가** | 가만히 두고 10초. 숨쉬기·깜빡임·귀 흔들림으로 "멈춘 그림"이 아니다 |
| 2 | **출발이 무겁지 않은가** | 키를 누른 순간 반응. 하지만 미끄러지듯 튀어나가지도 않음 |
| 3 | **정지가 미끄러지지 않는가** | 키를 뗐을 때 발이 땅에 붙은 채 멈춤. 스케이팅 없음 |
| 4 | **방향 전환이 자연스러운가** | 180° 돌 때 몸이 통째로 스냅되지 않고 앞다리→몸→뒷다리 순으로 따라옴 |
| 5 | **발이 땅에 붙어 있는가** | 경사·계단에서 발이 뜨거나 파묻히지 않음 (§1-4 발 IK) |
| 6 | **속도와 애니 속도가 맞는가** | 걷기 클립 재생속도 × 보폭 = 실제 이동거리. 발이 헛돌지 않음 |
| 7 | **걷기(2족)↔질주(4족) 전환이 튀지 않는가** | 스탠스 전환(내려가기/일어나기) 중 속도가 끊기지 않고, 다리가 꼬이거나 순간이동하지 않음 |
| 8 | **점프에 무게가 있는가** | 예비동작 → 상승 → 착지 스쿼시. 착지 때 화면이 살짝 눌림 |
| 9 | **두 조작 방식이 같은 감촉인가** | WASD로 걷다가 클릭 이동으로 바꿔도 이질감·정지 없음 (기획서 §3-2 마지막 입력 규칙) |
| 10 | **5분 뒤에도 걷고 싶은가** | ★ 가장 중요. 목적 없이 돌아다니는 것만으로 기분이 좋은가 |

**10번이 ×이면 나머지 9개가 ○여도 통과가 아니다.** 07 §6-1: "재밌는지 판단. 이건 AI가 모릅니다."

### 1-2. 자주 나오는 증상과 원인

| 증상 | 원인 후보 | 손볼 곳 |
|---|---|---|
| 미끄러짐(스케이팅) | 이동 속도 > 애니 보폭 | 기획서 §3-3 속도 또는 클립 재생속도 |
| 발이 바닥에 파묻힘 | 발 IK 레이캐스트 오프셋 | §1-4 ① |
| 방향 전환이 로봇 같음 | 회전 속도가 너무 빠름, Turn 클립 미사용 | §3-3 회전 속도 ↓, Turn L/R 클립 연결 |
| 정지가 죽어 있음 | 절차적 레이어 미적용 | §1-4 ④⑤ |
| 클릭 이동으로 바꿀 때 멈칫 | 마지막 입력 규칙에서 속도 0 초기화 | 기획서 §3-2 |
| 점프가 가벼움 | 예비동작·스쿼시 없음 | §1-4 ⑥ |

### 1-3. 애니메이션 클립 자체의 최소 기준

AI 생성 클립(Meshy Animate 등)을 채택할지 판단하는 기준 ★ (08 A4~A7):

- 4발이 **교대로** 땅에 닿는가 (4족 보행 패턴이 무너지지 않았는가)
- 관절이 반대로 꺾이지 않는가
- 루프 클립의 첫 프레임과 끝 프레임이 이어지는가
- 발이 지면 높이 0을 뚫지 않는가

**이 4개를 만족하면 채택하고, 나머지는 §1-4 절차적 레이어로 끌어올린다.** 클립 자체를 완벽하게 만들려고 하지 않는다 — 그게 외주로 가는 지름길이다.

### 1-4. 절차적 레이어 판정 ★

> 07 §3-2 표 3행이 "품질기준 §1-4"로 참조하는 절. 구현 명세는 **기획서 §4-3**.
> 07 §3-2: **"모든 경우에 반드시. 클립 품질을 가장 크게 끌어올림."**

각 레이어가 실제로 동작하는지 확인하는 방법:

| # | 레이어 | 확인 방법 | ○ |
|---|---|---|---|
| 1 | 발 IK | 경사 15° 위를 걷게 함 | 네 발이 경사면에 붙어 있음 |
| 2 | 머리 룩앳 | 옆에 NPC를 두고 지나감 | 지나가며 고개가 따라 돌아감. 목이 부자연스럽게 꺾이지 않음 |
| 3 | 스프링본 | 급정지 / 급회전 | 귀와 꼬리가 관성으로 늦게 따라옴. 진동이 발산하지 않음 |
| 4 | 숨쉬기 | 10초 정지 | 가슴이 느리게 오르내림. 이동 중에는 꺼짐 |
| 5 | 깜빡임 | 20초 관찰 | 3~6회 깜빡임. 규칙적이지 않음 |
| 6 | 스쿼시&스트레치 | 점프 후 착지 | 착지 순간 눌렸다 돌아옴 (0.12초) |

**6개 중 하나라도 ×면 §1-1 판정을 하지 않는다.** 순서가 거꾸로다 — 절차적 레이어를 먼저 켜고 나서 손맛을 본다.

### 1-5. 외주 판정 ★

> 08 A 하단: "위 전부 해보고도 품질기준 §1-1 체크가 안 되면 그때만 이동 8클립 인간 외주(100~200만). 그전엔 하지 않음."

외주를 검토하려면 **아래를 전부 시도한 기록**이 있어야 한다:
1. Meshy Animate 4족 라이브러리 ★ (08 A4)
2. Anything World 교차 검증 ★ (08 A4)
3. Cascadeur 키포즈 보정 ★ (08 A5)
4. 에셋스토어 강아지 팩 구매 + 리타겟 ($30~100) ★ (08 A4)
5. §1-4 절차적 레이어 6개 전부 적용

**1~5를 다 하고도 §1-1이 8개 이하면** 그때 외주. 기록은 `docs/perf_log.md` 에.

## 2. 영상미

### 2-1. 스크린샷 테스트 ★

> 07 §4가 "품질기준 §2-1 스크린샷 테스트"로 참조하는 절.

**방법**: 게임을 실행해 아무 지점에서 스크린샷 1장을 찍는다. **그 한 장을 처음 보는 사람에게 보여준다.**

**통과 조건: "이거 게임이야, 그림이야?" 또는 "무슨 애니메이션이야?"라는 반응이 나올 것.**
"게임 스크린샷이네"라는 반응이면 실패다.

세부 체크 (6개 중 5개 이상 ○):

| # | 체크 | ○의 기준 |
|---|---|---|
| 1 | **아웃라인** | 캐릭터·소품에 굵은 손그림 선이 있고, 거리에 따라 굵기가 튀지 않음 |
| 2 | **그림자가 웜톤인가** | 회색/파란 그림자가 아니라 따뜻한 색. 2단 램프로 딱 끊김 (기술사양 §3-1) |
| 3 | **종이 그레인** | 화면 전체에 종이 질감. 카메라가 움직여도 그레인은 화면에 고정 (기술사양 §3-2) |
| 4 | **3D와 2D가 한 세계인가** | 3D 누룽이·바닥이 2D 배경 그림에서 튀지 않음. **FOV 28 망원 압축이 이걸 만든다** |
| 5 | **팔레트 통일** | 화면 안 색이 같은 팔레트에서 나온 것처럼 보임. 튀는 채도 없음 |
| 6 | **지평선 62%** | 격자 오버레이를 켰을 때 배경 지평선이 62% 선에 맞음 ★ (07 §3-3) |

### 2-2. 배경 일관성 (200챕터가 한 세계로 보이는가) ★

07 §6-3: "일관성 감시. 200챕터가 한 세계로 보이는지 — 검수 눈"

- **월 1회 몽타주 점검**: 그때까지 만든 배경을 4×5 격자로 붙여 한 장으로 본다. 튀는 것이 눈에 띄면 그것만 재생성
- 튀는 원인 대부분은 **LoRA 없이 프롬프트만 쓴 배치** ★ (07 §7). 파이프라인 §3 참조
- 팔레트 양자화가 자동으로 돌았는지 확인 ★ (08 C10)

### 2-3. 움직이는 화면의 품질

정지 스크린샷이 좋아도 움직이면 무너지는 경우:

| # | 체크 | ○의 기준 |
|---|---|---|
| 1 | 시차가 자연스러운가 | 걸을 때 레이어가 밀리지만 "판이 미끄러지는" 느낌은 없음 (대형스크롤맵 §2-1) |
| 2 | 세그먼트 이음새 | 걸어서 지나갈 때 배경 경계가 보이지 않음 |
| 3 | 카메라가 멀미를 유발하지 않는가 | 좌우로 왔다갔다해도 화면이 계속 흔들리지 않음 (기술사양 §2-3 안전 상자) |
| 4 | 바람·흔들림 | 나무·풀·천이 미세하게 움직임. 정지 화면이 아님 (08 C6, D3) |
| 5 | 프레임이 일정한가 | 세그먼트 로드 순간 프레임 드랍이 눈에 띄지 않음 (대형스크롤맵 §3) |

### 2-4. 영화 애니메이션 룩 체크 (★디렉터 확정 2026-08-17 — 품질 1원칙)

"게임처럼 보이는 것"과 "애니메이션 영화처럼 보이는 것"을 가르는 요소. §2-1을 통과해도 아래가 무너지면 영화가 아니다.

| # | 요소 | 영화가 되는 조건 | 게임처럼 보이는 실패 |
|---|---|---|---|
| 1 | **프레임 안정** | 항상 60fps, 미세 스터터 없음 | 로드 순간 프레임 튐 (스트리밍 §3이 막는 것) |
| 2 | **카메라 절제** | 컷 개념 — 흔들림 없이 느리게 미끄러짐. 캐릭터에 딱 붙지 않음 | 캐릭터 중앙 고정 추적, 기계적 즉시 반응 |
| 3 | **모든 것이 미세하게 움직임** | 귀·꼬리·나뭇잎·풀·옷자락 — 정지 프레임이 없음 | 배경이 정지 그림 (D3 바람 셰이더, 스프링본) |
| 4 | **빛의 방향이 그림에 있음** | 배경 원화 자체에 빛·그림자가 그려져 있고 시간대 LUT와 일치 | 균일 조명의 플랫 배경 |
| 5 | **연출된 순간** | 챕터 진입·클리어에 카메라 워크 한 컷 (DSL로 연출) | UI 팝업으로 시작·종료 |
| 6 | **화면 마감** | 종이 그레인 + 비네트 + LUT + (무비모드 레터박스 2.35:1 옵션) | 포스트 없는 생 렌더 |
| 7 | **애니메이션 원칙** | 예비동작·팔로스루·스쿼시 (절차 레이어 + 클립 품질) | 등속 로봇 모션 |
| 8 | **음향의 층** | BGM 아래 환경음·발소리·옷깃 소리가 겹침 | BGM 단독 |

**판정법**: 10초 플레이 영상을 녹화해 참조 영상(Pika 원본) 옆에 놓고 재생 — 같은 시리즈의 다른 컷으로 보이면 통과.

## 3. 판정 절차

### 3-1. M0 관문 (룩)

1. 회색 박스 맵 + 툰 셰이더 + 종이 그레인 + 누룽이
2. **§2-1 스크린샷 테스트** 실행
3. 통과 → M1로. 실패 → 셰이더·LUT·그레인 수치 조정 반복

### 3-2. M1 관문 (움직임)

1. §1-4 절차적 레이어 6개 확인 (전부 ○ 필수)
2. 회색 박스에서 5분 플레이
3. **§1-1 체크 10개**, 9개 이상 + 10번 ○
4. 통과 → M2로. 실패 → §1-2 표로 원인 추적. 클립 부족이면 §1-5

### 3-3. P4 관문 (배경 대량 생산 직전) ★

**07 §4의 핵심 규칙**: §1-1 과 §2-1 을 **둘 다** 통과하기 전에는 배경 625장 생산을 시작하지 않는다.

이유: 룩이 안 정해진 상태로 625장을 뽑으면 전부 다시 만들어야 한다. Scenario 구독비와 검수 시간이 통째로 날아간다.

### 3-4. 기록

각 판정 결과를 `docs/perf_log.md` 에 남긴다:

```markdown
## 2026-09-15 M1 관문 1차
§1-4: 1○ 2○ 3× (꼬리 진동 발산) 4○ 5○ 6○  → 판정 보류
조치: SpringBone damping 0.2 → 0.35
```

## 4. 디렉터가 Claude Code 에게 말하는 법

Claude Code 는 화면을 못 본다 ★ (07 §2-4). 그래서 이렇게 말한다:

| 대신 | 이렇게 |
|---|---|
| "이상해요" | "§1-1 3번이 ×입니다. 키를 뗐는데 30cm쯤 미끄러집니다" |
| "느낌이 안 나요" | "§2-1 2번이 ×입니다. 그림자가 파랗습니다" |
| "고쳐주세요" | "§1-2 표에서 원인 후보를 확인하고, 무엇이 원인이라 생각하는지 한 줄 먼저 말한 다음 고쳐주세요" ★ (07 §9) |

**번호로 말하면 AI가 문서를 찾아간다.** 이것이 설계 문서를 절 번호로 관리하는 이유다.
