## 0. 전제

| 당신이 하는 것 | AI가 하는 것 |
|---|---|
| 무엇을 만들지 결정 | 어떻게 만들지 + 실제 제작 |
| 결과물 보고 좋다/나쁘다 판단 | 수정 반복 |
| 톤·스타일·재미 감각 유지 | 코드, 3D, 그림, 사운드, 문서, 테스트 |
| 툴 결제, 라이선스 확인 | — |
| 지인 테스트 돌리고 피드백 정리 | 피드백을 수정 작업으로 변환 |

**코딩은 0줄 합니다.** 대신 아래 두 가지는 배워야 합니다: ① AI에게 명확히 말하는 법 ② 결과가 맞는지 보는 눈. 둘 다 이 문서와 앞선 6개 설계 문서가 도와줍니다.

## 2. 핵심 축: Claude Code + Unity MCP

비개발자 프로젝트의 성패는 여기서 갈립니다.

### 2-1. 무엇이 되는가
Unity 공식 MCP 서버(Unity 6, AI 베타) 또는 오픈소스 Unity MCP(CoplayDev 등)를 연결하면 Claude Code가:
- 씬 생성, GameObject 배치, 컴포넌트 추가·값 수정
- C# 스크립트 작성 → 컴파일 → **콘솔 에러 읽고 스스로 수정**
- 패키지 설치, 프로젝트 설정 변경
- 테스트 실행, 빌드 실행

즉 **"카메라를 FOV 28 망원으로 바꾸고 누룽이 뒤에서 따라오게 해줘"**라고 말하면 실제로 그렇게 됩니다.

### 2-2. 세팅 (1회, Claude Code가 안내)
1. Unity Hub → Unity 6 LTS 설치 (Android Build Support 포함)
2. URP 템플릿으로 프로젝트 생성
3. Claude Code 설치, 프로젝트 폴더에서 실행
4. Claude Code에게: "이 프로젝트에 Unity MCP를 연결해줘 (Unity 공식 MCP 또는 CoplayDev unity-mcp). 세팅 순서를 하나씩 알려주고, 내가 Unity에서 클릭해야 할 것은 정확히 말해줘"
5. `docs/` 폴더에 설계 문서 6개 + 이 문서 넣기
6. `CLAUDE.md` 작성 요청: "docs를 읽고, 이 프로젝트의 규칙(FOV 28, 팔레트, 바닥 3D/그림 2D, 챕터 JSON 구조 등)을 CLAUDE.md에 정리해서 앞으로 모든 작업에서 지키게 해줘"

### 2-3. 지시하는 법 (이것만 익히면 됨)
- **한 번에 하나**: "카메라 세팅해줘" ○ / "카메라랑 셰이더랑 이동 다 해줘" ✗
- **문서를 가리키기**: "docs/카메라 문서 §1-1 값대로" — 숫자를 외울 필요 없음
- **결과 확인 요청**: "끝나면 Play 모드에서 확인할 방법을 알려줘"
- **이상하면 그대로 말하기**: "누룽이가 바닥에 파묻혀 보여" — 원인은 AI가 찾음
- **되돌리기**: git을 처음부터 쓰게 시키고 "어제 상태로 되돌려줘"가 통하게 함

### 2-4. Claude Code가 못 하는 것
- Unity 에디터 화면을 **보지는** 못함 (MCP는 데이터로 읽음). "느낌이 이상하다"는 당신이 봐야 함
- 예쁜지 판단
- 폰에 APK 설치 (파일은 만들어 줌)

## 3. 영역별 상세 워크플로

### 3-1. 캐릭터 3D (누룽이)
1. 첨부 6방향 시트를 Meshy에 업로드 → 이미지→3D. 3~5회 생성, 가장 나은 것 선택
2. Tripo로도 같은 시트로 생성 → 비교 (Tripo가 쿼드 토폴로지라 애니메이션에 유리한 경우 많음)
3. 선택한 모델을 Claude Code에게: "Blender로 이 모델의 비율을 시트에 맞게 조정하는 스크립트를 짜고 실행해줘. 눈·코·귀 위치를 정면 시트와 비교해서 맞춰줘" (Blender는 Python으로 조작 가능 → Claude Code가 직접 함)
4. 툰 셰이딩은 텍스처가 아니라 셰이더가 하므로, 모델은 **플랫 컬러 3~4색**이면 충분. AI가 만든 복잡한 텍스처는 버리고 단색으로 교체 요청
5. 리깅: Meshy/Tripo 오토리깅 → 4족이라 품질 편차 큼. 안 되면 Claude Code에게 "Blender Rigify 4족 메타리그로 리깅 스크립트 작성"

**사람 몫**: 3~5개 후보 중 고르기, "귀가 너무 크다" 수준의 피드백.

### 3-2. 애니메이션 — AI로 만들고, 부족하면 사서 리타겟 (외주는 최후) ⚠

**현실(2026 중반)**: 4족 AI 애니메이션이 크게 좋아졌습니다. Meshy Animate가 4족을 인식하고 600+ 클립 라이브러리를 적용해 주며, Anything World "Animate Anything"은 동물 전용 자동 리깅+걷기·뛰기·Idle·점프 생성, 3D AI Studio(Prism)도 4족 리깅을 지원합니다. 에셋스토어에는 애니메이션이 포함된 스타일라이즈드 강아지 팩이 여럿 있어 리타겟해서 "사올" 수도 있습니다.

| 순서 | 방법 | 비용 |
|---|---|---|
| **1. AI 생성 (기본)** | Meshy로 리깅 + Meshy Animate 4족 라이브러리로 이동·점프·자세 클립 → 같은 리그라 리타겟 불필요. 없는 동작(Push·Bite·Crawl·감정)은 **Cascadeur** 키포즈 + AutoPhysics. Anything World로 교차 검증 | Meshy 구독 포함, Cascadeur 무료 |
| **2. 구매 + 리타겟** | 품질 부족 시 에셋스토어 강아지 애니 팩(Synty POLYGON Dog $99 등) 구매 → Claude Code가 Blender 본 매핑으로 누룽이 리그에 리타겟 | $30~100 |
| **3. Unity 절차적 레이어** | 발 IK·머리 룩앳·스프링본·숨쉬기·깜빡임·스쿼시 — **모든 경우에 반드시** (품질기준 §1-4). 클립 품질을 가장 크게 끌어올림 | 0, Claude Code |
| **4. 인간 외주 (최후)** | 위 전부 시도 후 품질기준 §1-1 체크가 안 될 때만, 이동 8클립 | 100~200만 |

**얼굴 표정은 텍스처 스왑**(동물의 숲 방식): 3D 조형 대신 Scenario로 눈·입 스프라이트 시트 6종 생성 → 셰이더 스왑. 블렌드셰이프보다 훨씬 쉽고 만화 느낌에 맞음.

**항목별 정확한 조달처는 「에셋 조달표」 §A 참조.**

### 3-3. 배경 (500장 세그먼트 + 컷아웃)
1. **앵커 30장**: Midjourney 또는 Scenario에서 첨부 이미지·영상 컷 참고로 생성 → 당신이 30장 선정. **시점(15° 부감, 지평선 62%)과 팔레트 통일**을 프롬프트에 고정 (Claude에게 프롬프트 작성 요청)
2. **Scenario에서 LoRA 학습** (업로드 → 학습 버튼. 30분)
3. **프롬프트 매트릭스 CSV**: Claude 채팅에 "킷 25개 × 세그먼트 25개 매트릭스 CSV 만들어줘" → 받아서 검토
4. **배치 생성**: Scenario 배치 기능 또는 Claude Code가 Scenario API로 자동 호출 (API 지원). 후보 3장/슬롯
5. **검수**: 당신, 장당 30초. 리젝 기준은 파이프라인 문서 §8
6. **후처리**: Claude Code 스크립트가 팔레트 양자화·이음새 크로스페이드·WebP·메타 JSON 전부 자동
7. **컷아웃**: Scenario 투명 배경 생성 또는 생성 후 Claude Code가 rembg로 배경 제거

**로컬 ComfyUI는?** 500장 규모면 비용상 유리하지만 세팅이 기술적. **Claude Code에게 세팅을 시키면 됩니다** — 다만 GPU 12GB+ PC가 있어야. 없으면 Scenario로 (500장 × 3후보 = 1,500장 → Scenario Pro 이상 플랜, 월 $99 정도 2~3개월).

### 3-4. 코드·시스템 (전부 Claude Code)
설계 문서 순서대로 지시하면 됩니다. 각 지시는 한 문장:
- "docs/기술사양 §2-3의 SafeBoxCamera 원근 버전을 만들고 씬에 붙여줘"
- "docs/대형스크롤맵 §1-1 Cinemachine 설정으로 추적 카메라 만들어줘"
- "docs/기획서 §3 두 조작 방식 + 마지막 입력 규칙 구현해줘. 회색 큐브로 테스트 씬도"
- "docs/기획서 §4-3의 발 IK, 룩앳, 스프링본을 누룽이에 세팅해줘"
- "docs/대형스크롤맵 §3 세그먼트 스트리밍 구현"
- "docs/대형스크롤맵 §4 챕터 JSON 로더 + 에디터 툴"
- "docs/기술사양 §5 Windows 빌드 설정하고 EXE 빌드해줘" (Android는 M2 이후)

### 3-5. 사운드
- Suno: "잔잔한 어쿠스틱 기타와 피아노, 힐링 게임 BGM, 루프 가능, 90초" → 챕터 킷당 1곡. 상업 이용은 유료 플랜
- ElevenLabs Sound Effects: "small dog footsteps on wood floor", "puppy sniffing", "soft bark" — 개인 배포면 무료 티어 가능
- 통합은 Claude Code: "발소리를 바닥 재질별로 재생하는 시스템 만들어줘"

### 3-6. 테스트
- Claude Code + Unity MCP: Play 모드 실행, 콘솔 에러 자동 수정, 유닛 테스트 작성
- **당신**: 폰으로 10분 플레이 → "느낌" 피드백. 이건 대체 불가
- 지인 테스트 후 피드백을 그대로 Claude에게 붙여넣기 → 수정 작업 목록으로 변환 → Claude Code 실행

## 6. AI가 못 하는 것 — 당신이 반드시 할 것

1. **재밌는지 판단.** M1 회색 박스에서 5분 돌아다녔을 때 기분 좋은가. 이건 AI가 모릅니다
2. **스타일 확정.** 앵커 30장 고르기, "이 톤이다" 결정
3. **일관성 감시.** 200챕터가 한 세계로 보이는지 — 검수 눈
4. **범위 자르기.** AI는 시키면 다 만들려 함. "이건 안 만든다"는 당신 몫 (기획서 §12 "하지 않을 것")
5. **폰으로 실제 플레이.** 에뮬레이터·데이터로는 손맛을 모름
6. **결제와 라이선스.** 툴별 상업 이용 조건은 사람이 확인

## 7. AI 의존 프로젝트의 흔한 실패와 대비

| 실패 | 원인 | 대비 |
|---|---|---|
| 코드가 점점 엉켜서 나중에 아무도(AI도) 못 고침 | 규칙 없이 기능만 추가 | **CLAUDE.md**에 아키텍처 규칙 고정, 매 기능마다 "기존 구조에 맞는지 확인" 요청, git 필수 |
| 배경이 갈수록 스타일이 흐트러짐 | LoRA 없이 프롬프트만 | LoRA 필수, 팔레트 양자화 자동, 검수 |
| 3D 모델이 리깅·애니에서 깨짐 | 토폴로지 나쁨 | Tripo 쿼드 리토폴로지, 초반에 걷기 애니까지 붙여서 확인 |

| 처음에 안 뚫은 Android 빌드가 마지막에 막힘 | 순서 | **첫 주에 빈 프로젝트 APK 빌드**부터 |
