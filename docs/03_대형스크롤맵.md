# 누룽이의 세계 — 대형 스크롤 맵

> **문서 상태: 초안(v0.1)**
> ★ = 07/08 문서에 근거가 있는 확정값. 표시 없는 값 = 제안값, 디렉터 확정 필요.
> §1-1 / §3 / §4 는 다른 문서가 번호로 참조하므로 **절 번호를 바꾸지 말 것**.

## 0. 이 문서가 푸는 문제

챕터 하나는 좌우로 60~150m 길다. 배경은 2D 그림 세그먼트 6~12장이 이어 붙어 있고, 바닥은 3D다 ★ (07 §2-2). 여기서 세 가지를 풀어야 한다:

1. **카메라가 어떻게 따라가는가** → §1
2. **긴 맵을 어떻게 끊김 없이 로드/언로드하는가** → §3
3. **어디에 무엇을 놓는지를 어떻게 데이터로 관리하는가** → §4

## 1. 추적 카메라

### 1-1. Cinemachine 설정 ★

> 07 §3-4 가 "docs/대형스크롤맵 §1-1 Cinemachine 설정으로 추적 카메라 만들어줘"로 참조하는 절.

**구성**: `CinemachineBrain`(Main Camera) + `CinemachineCamera` 1개 + 커스텀 Extension `SafeBoxExtension`

| 항목 | 설정 | 값 |
|---|---|---|
| Lens | Perspective, **FOV 28** ★ | 기술사양 §2-1 |
| Follow | 누룽이 루트 | |
| LookAt | 비움 (회전 고정) | 부감 15° 고정 ★ |
| Body | **Position Composer** | |
| ─ Camera Distance | 12 | |
| ─ Dead Zone 가로 | 0.36 (= 화면 ±18%) | 기술사양 §2-3 |
| ─ Dead Zone 세로 | 0.20 (= 화면 ±10%) | 기술사양 §2-3 |
| ─ Damping X / Y / Z | 0.25 / 0.45 / 0.3 | 세로를 느리게 |
| ─ Screen X / Y | 0.5 / 0.55 | 지평선 62% 정합 (기술사양 §2-2) |
| Aim | **Do Nothing** — 회전은 고정값 (15°, 0, 0) | |
| Noise | 없음 (손떨림은 이 게임 톤이 아님) | |

**커스텀 Extension 이 하는 일** (Cinemachine 만으로 안 되는 것):
1. **원근 보정** — Dead Zone 은 뷰포트 기준이라 대부분 맞지만, 누룽이가 깊이 방향으로 이동하면 화면상 크기가 변한다. depth 변화에 맞춰 거리를 미세 보정 (기술사양 §2-3)
2. **속도 리드** — 이동 방향 최대 1.5m 선행, 방향 전환 시 0.4s 블렌드
3. **맵 경계 클램프** — §1-2
4. **세로 모드 전환** — 화면비가 1.0 미만이면 거리 ×1.35, Dead Zone 교체 (기술사양 §2-4)

### 1-2. 경계 클램프

챕터 양 끝에서 카메라가 맵 밖(배경이 없는 빈 공간)을 비추면 안 된다.

- 챕터 JSON의 `bounds.minX` / `maxX` 를 읽어 카메라 X를 클램프
- **판정은 카메라 위치가 아니라 화면 가장자리 기준**: 카메라 프러스텀이 배경 세그먼트가 깔린 구간을 벗어나지 않게
- 세로 모드에서는 가로 시야가 좁아 클램프 여유가 늘어난다 — 자동 계산

### 1-3. 촬영 모드 전환

촬영 모드에서는 이 카메라가 꺼지고 자유 카메라로 넘어간다. 상세는 **docs/06_촬영모드.md**

## 2. 맵의 물리적 구성

### 2-1. 레이어 구조

```
       ← 카메라 방향

  [원경 하늘]        Z = +40   시차 0.1  ★ 08 C8
  [배경 세그먼트]    Z = +14   시차 0.35  ← 그림 (2D)
  [컷아웃 중경]      Z = +7    시차 0.6   ★ 08 C5
  [컷아웃 근경]      Z = +2    시차 0.85
  ─────────────────────────────────────
  [바닥 + 누룽이]    Z = 0     시차 1.0   ← 3D ★ 07 §2-2
  [컷아웃 전경]      Z = -3    시차 1.3   (누룽이 앞을 가림)
```

- 시차는 카메라 X 이동량 × 계수로 각 레이어를 반대로 밀어 만든다
- **FOV 28 망원이라 시차가 약하게 보이는 게 정상.** 과하게 주면 2D 그림이 "판"으로 들통난다

### 2-2. 바닥

- 3D 메시. 좌우로 길고 깊이 3~5m (기획서 §5-2)
- 재질 태그 6종(흙/풀/나무/타일/자갈/물) → 발소리 연동 (기획서 §10)
- 경사·계단 있음 → 발 IK 가 이걸 처리 (기획서 §4-3)
- 보이지 않는 벽으로 앞뒤 이동 제한

### 2-3. 세그먼트 규격

| 항목 | 값 |
|---|---|
| 1장이 덮는 월드 폭 | **12m** |
| 텍스처 | 2048×1152 WebP ★ (기술사양 §4) |
| 이음 여백 | 좌우 각 64px, 크로스페이드로 접합 ★ (07 §3-3 6) |
| 세그먼트 타입 | 25종 (L/M/R/코너/입구/광장 …) ★ (08 C3) |

## 3. 세그먼트 스트리밍

> 07 §3-4 가 "docs/대형스크롤맵 §3 세그먼트 스트리밍 구현"으로 참조하는 절.

### 3-1. 원칙

챕터 전체(최대 12장 × 2048×1152)를 한 번에 메모리에 올리면 Android 512MB 예산을 넘긴다. **현재 위치 주변만 들고 있는다.**

### 3-2. 윈도우

```
세그먼트 인덱스:  0   1   2   3   4   5   6   7   8
누룽이 위치:              ▲(3번)
로드 상태:       ─   ─   L   L   ●   L   L   ─   ─
                         ↑           ↑
                    prefetch 2   prefetch 2
```

- **현재 ±2 = 최대 5장 동시 로드** ★ (기술사양 §4)
- 로드: **Addressables** 비동기 ★ (08 G3)
- 언로드: 윈도우를 벗어난 뒤 **1.5초 유예**를 두고 해제 (경계에서 왔다갔다 할 때 로드/언로드가 튀는 것 방지)

### 3-3. 히스테리시스

경계에 서서 조금씩 움직일 때 로드가 반복되면 프레임이 튄다.

- 세그먼트 전환 판정선을 **진입 방향에 따라 ±1.5m 어긋나게** 둔다
- 즉 오른쪽으로 갈 때의 전환 지점과 왼쪽으로 갈 때의 전환 지점이 다르다

### 3-4. 로드 실패·지연 대응

- 프리페치가 늦어 다음 세그먼트가 준비 안 된 경우: **누룽이를 멈추지 않는다.** 대신 마지막 세그먼트의 가장자리 색으로 채운 단색 판을 임시로 세운다
- 로드 실패 시 콘솔 에러 + 해당 슬롯 스킵. 게임은 계속 진행

### 3-5. 컷아웃·소품

- 컷아웃과 소품도 세그먼트에 소속시켜 같이 로드/언로드
- 물리 있는 소품(밀 수 있는 상자)은 언로드 시 **위치를 저장**했다가 재로드 때 복원

### 3-6. 검증 방법 (디렉터가 확인하는 법)

- 챕터 끝에서 끝까지 뛰어서 왕복 3회 — 끊김·검은 화면·소품 사라짐이 없어야 함
- Profiler 에서 메모리가 톱니처럼 오르내리되 **우상향하지 않아야** 함 (우상향 = 언로드 실패)

## 4. 챕터 JSON + 에디터 툴

> 07 §3-4 가 "docs/대형스크롤맵 §4 챕터 JSON 로더 + 에디터 툴"로 참조하는 절.
> **씬에 좌표를 하드코딩하지 않는다** (기술사양 §8-4). 챕터는 전부 이 JSON이다.

### 4-1. 구조

**위치**: `unity/Assets/Data/Chapters/<kit>/<chapter_id>.json`

```json
{

  "kit": "alley",
  "title": "골목 첫 산책",
  "timeOfDay": "morning",
  "weather": "clear",
  "bounds": { "minX": 0, "maxX": 96 },
  "startX": 4,
  "goalX": 92,
  "bgm": "bgm_alley",
  "ambience": "amb_city_far",

  "segments": [
    { "index": 0, "type": "entrance", "asset": "bg/alley/entrance_morning", "x": 0 },
    { "index": 1, "type": "M",        "asset": "bg/alley/m01_morning",      "x": 12 },
```

### 4-2. 규칙

- **모든 배치는 X 좌표 하나로 지정.** 깊이(Z)는 `layer` 가, 높이(Y)는 바닥이 결정 → 배치가 1차원이라 에디터 툴이 단순해짐
- `asset` 은 Addressables 주소
- `line` 은 누룽이 속마음 한 줄 (기획서 §6). 대화 트리 없음
- 로더는 JSON 스키마 검증 후 로드. 필드가 빠지면 **기본값으로 진행하고 콘솔에 경고** (챕터가 200개라 하나 때문에 멈추면 안 됨)

### 4-3. 에디터 툴 ★ (08 G8)

**`Tools/누룽이/챕터 에디터` — 커스텀 EditorWindow**

07 §1 표: "챕터 데이터 배치 = Claude Code 자동 초안 + 에디터 툴 / 사람이 맵당 10~20분 손보기"

기능:
1. **가로 타임라인 뷰** — X축이 곧 챕터. 세그먼트·상호작용·수집품을 점으로 표시, 드래그로 이동
2. **씬 뷰 동기화** — 씬에서 오브젝트를 옮기면 JSON의 X가 갱신됨 (역방향도)
3. **자동 초안 버튼** — 킷·길이·시간대를 고르면 세그먼트 배열과 상호작용 후보를 자동 생성 → 사람이 손봄
4. **검증 버튼** — 아래 체크를 돌리고 문제 목록 표시
   - 세그먼트 X가 12m 간격으로 연속인가
   - `goalX` 가 `bounds` 안인가
   - 필수 상호작용(`required: true`)이 최소 1개 있는가
   - 상호작용 사이 간격이 8m 이상인가 (너무 몰리면 산책이 아니라 체험관)
   - 참조된 Addressables 주소가 실제로 존재하는가
5. **플레이 프리뷰** — 이 챕터만 바로 Play

### 4-4. 챕터 수에 대한 규칙

- 챕터 200개는 **상한이지 목표가 아니다** (기획서 §5-1)
- M2 완료 시점에 **실제로 1챕터를 만드는 데 걸린 시간**을 측정해 `docs/perf_log.md` 에 기록하고, 남은 기간으로 챕터 수를 재산정한다
- 자동 초안이 아무리 좋아도 사람 검수 10~20분은 줄어들지 않는다 ★ (07 §1)

## 5. 좌표계 약속

| 축 | 의미 |
|---|---|
| **+X** | 챕터 진행 방향 (오른쪽) |
| **+Y** | 위 |
| **+Z** | 화면 안쪽 (카메라에서 멀어지는 쪽) |

- 챕터 시작점의 바닥이 원점 `(0, 0, 0)`
- 모든 JSON 좌표는 이 로컬 좌표계
- **왼쪽으로 진행하는 챕터를 만들지 않는다.** 필요하면 챕터 전체를 `flipX` (배경 625장을 좌우 양쪽으로 만들 여유가 없음)
