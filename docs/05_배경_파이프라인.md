## 2. P1 — 앵커 30장 ★ (07 §3-3 1, 08 C1)

**앵커가 이 게임의 스타일을 결정한다.** 이후 625장은 전부 이 30장을 닮는다.

### 2-1. 고정 프롬프트 규칙 ★ (07 §9)

모든 앵커·세그먼트 프롬프트에 반드시 들어가는 조건:

```
플랫 파스텔 카툰, 종이 질감, 굵은 아웃라인,
캐릭터 없음,
정면 15° 부감,
지평선은 세로 62% 위치,
바닥은 화면 아래 1/3 평평하게,
좌우 이음 여백
```

- **15° 부감 / 지평선 62%** 는 카메라 세팅(기술사양 §2-1, §2-2)과 물리적으로 같은 값이어야 한다. 여기가 어긋나면 3D 바닥과 2D 그림이 따로 논다
- **캐릭터 없음**: 사람·동물이 그려져 들어오면 못 쓴다. 컷아웃으로 따로 만든다

### 2-2. 선정 기준

- 25개 킷을 고루 커버 (골목·공원·지하철·사무실·해변 …)
- 시간대는 앵커 단계에서 **낮 하나로 통일** (변주는 P2 이후)
- 30장을 나란히 놓았을 때 **한 사람이 그린 것처럼 보일 것**

**이 30장 고르기가 07 §6-2 "스타일 확정 — 당신 몫"이다.** AI가 대신 못 한다.

## 3. P2 — LoRA 학습 ★ (08 C2)

- Scenario 에 앵커 30장 업로드 → 학습 (약 30분)
- 학습 후 테스트 생성 5장 → 앵커와 같은 톤인지 확인. 아니면 앵커를 갈아 재학습
- LoRA 버전을 기록: `lora_v1`, `lora_v2` … 어떤 배경이 어떤 LoRA로 나왔는지 `asset_sources.csv` 에 남긴다 (기술사양 §6)

**07 §7**: "배경이 갈수록 스타일이 흐트러짐 — 원인: LoRA 없이 프롬프트만. → LoRA 필수."

**대안**: 로컬 ComfyUI + FLUX LoRA (GPU 12GB+ 필요, 비용 0) ★ (08 C2)

## 4. P3 — 프롬프트 매트릭스 ★ (07 §3-3 3)

Claude 채팅에 요청: **"킷 25개 × 세그먼트 25개 매트릭스 CSV 만들어줘"**

`tools/bg_matrix.csv`:

```csv
slot_id,kit,segment_type,time,prompt,neg_prompt,seed_group
alley_M01,alley,M,day,"<고정 규칙> + 좁은 골목, 낡은 벽돌담, 전봇대, 화분","사람, 동물, 텍스트",1001
alley_L01,alley,L,day,"<고정 규칙> + 골목 왼쪽 끝, 큰 건물 모서리","사람, 동물, 텍스트",1001
park_M03,park,M,day,"<고정 규칙> + 잔디밭과 벤치, 큰 나무","사람, 동물, 텍스트",1002
```

- 세그먼트 타입 25종은 대형스크롤맵 §2-3 과 같은 목록을 쓴다 (L/M/R/코너/입구/광장 …)
- 같은 킷은 `seed_group` 을 공유해 톤이 흔들리지 않게

## 5. P4 — 배치 생성 ★ (07 §3-3 4, 08 C3)

- Scenario 배치 기능 또는 **Scenario API 를 Claude Code 스크립트로 호출**
- 슬롯당 후보 **3장**
- 출력: `art_raw/<kit>/<slot_id>_<n>.png`
- 진행 로그를 남겨 중단 후 재개 가능하게 (1,875장은 한 번에 안 끝난다)

## 6. P5 — 검수 ★ (07 §3-3 5)

- **디렉터가 장당 30초**, 3장 중 1장 선택 또는 전부 리젝
- 판정 기준은 **§8**
- 도구: Claude Code 가 만드는 간단한 로컬 검수 뷰어 (3장을 나란히 보여주고 1/2/3/R 키로 선택) — 브라우저 HTML이면 충분
- 결과: `tools/bg_picks.csv` (`slot_id, picked_file, verdict, note`)

**리젝된 슬롯은 프롬프트를 손봐 재생성 큐에 넣는다.** 리젝률 30%를 예산에 미리 넣어둔다.

## 7. P6 — 후처리 ★ (07 §3-3 6, 08 C10)

Claude Code Python 스크립트(Pillow)가 **전자동**으로:

| # | 처리 | 상세 |
|---|---|---|
| 1 | 크롭·리사이즈 | 2048×1152 (기술사양 §4) |
| 2 | **팔레트 양자화** | 프로젝트 공통 팔레트로 색 통일 ★ — 스타일 흐트러짐 방지 |
| 3 | 지평선 검증 | 62% ±2% 밖이면 경고 로그 (사람이 다시 봄) |
| 4 | **이음새 크로스페이드** | 좌우 64px 여백을 인접 세그먼트와 블렌드 |
| 5 | WebP 변환 | 품질 85 |
| 6 | 메타 JSON | `{slot_id, kit, type, time, lora, w, h, horizon_pct, created}` |
| 7 | CSV 기록 | `docs/asset_sources.csv` 에 자동 추가 (기술사양 §6) |

**출력**: `unity/Assets/Art/BG/<kit>/<slot_id>_<time>.webp` + `.meta.json`

## 8. 리젝 기준

> 07 §3-3 5 가 "리젝 기준은 파이프라인 문서 §8"로 참조하는 절.
> **하나라도 해당하면 리젝.** 고민하지 말고 다음 장으로 — 30초 안에 판단하기 위한 목록이다.

### 8-1. 즉시 리젝 (고칠 수 없음)

| # | 사유 | 왜 |
|---|---|---|
| 1 | **사람·동물이 그려져 있음** | NPC는 3D/컷아웃으로 따로 만든다. 그림에 박히면 못 지움 |
| 2 | **지평선이 62%에서 크게 벗어남** | 3D 바닥과 정합이 깨짐 (기술사양 §2-2) |
| 3 | **부감 각도가 다름** | 위에서 내려다보거나 정면에서 본 그림 |
| 4 | **바닥이 평평하지 않음** | 화면 아래 1/3이 3D 바닥에 가려질 자리인데 디테일이 꽉 차 있으면 낭비 |
| 5 | **좌우 이음 여백 없음** | 가장자리에 큰 구조물이 잘려 있으면 이어붙일 수 없음 |
| 6 | **원근 소실점이 여러 개** | AI 배경의 대표 실패. 건물 선들이 서로 다른 곳으로 모임 |
| 7 | **글자·간판 문자가 들어감** | 깨진 글자는 몰입을 깬다 |
| 8 | **팔레트 이탈** | 형광·고채도. 양자화로도 안 살아나는 정도 |

### 8-2. 조건부 리젝 (다른 후보가 있으면 리젝)

| # | 사유 |
|---|---|
| 9 | 아웃라인이 얇거나 없음 |
| 10 | 종이 질감이 약함 |
| 11 | 디테일 과다 — 킷의 다른 장과 밀도가 다름 |
| 12 | 좌우 대칭이 너무 강함 (이어 붙이면 반복이 눈에 띔) |
| 13 | 그림자 방향이 다른 장들과 반대 |

### 8-3. 리젝하지 않는 것 (후처리로 해결됨)

- 색이 조금 튐 → §7-2 팔레트 양자화
- 해상도 부족 → Real-ESRGAN ★ (08 C11)
- 가장자리 색 차이 → §7-4 크로스페이드
- 시간대가 낮인데 노을이 필요 → img2img 변주 ★ (08 C4)

**후처리로 되는 것을 리젝하지 않는 것이 검수 속도의 핵심이다.**

### 8-4. 킷 단위 재검토 신호

한 킷에서 **리젝률이 50%를 넘으면** 개별 재생성을 멈추고 그 킷의 프롬프트나 LoRA를 손본다. 나쁜 조건으로 계속 뽑는 것이 가장 비싸다.

## 10. P8 — Unity 반입

- Addressables 그룹: **킷 단위** (`bg_alley`, `bg_park` …) — 세그먼트 스트리밍이 킷 단위로 로드하기 때문 (대형스크롤맵 §3)
- 주소 규칙: `bg/<kit>/<slot_id>_<time>`
- 텍스처 임포트 설정: Sprite 아님, **Texture2D**, Mip 끔, Compression 은 Android ASTC 6×6
- 반입 후 **챕터 에디터의 검증 버튼**(대형스크롤맵 §4-3)이 주소 존재를 확인
